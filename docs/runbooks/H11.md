## 目标

交付可安装的 Windows 发布包、配置兼容策略、SQLite 迁移 dry-run 与回滚手册，并在干净目录完成一次端到端演练。

## 允许范围

- `packaging/`（发布脚本、默认配置样例、启动脚本）。
- `scripts/package.ps1`、`scripts/install.ps1`（如需要）。
- `docs/RELEASE.md`、`docs/runbooks/H11.md`、`CHANGELOG.md`。
- 根 `Cargo.toml` 的 workspace 版本号；不得改 crate 依赖版本。
- 为 `hive config migrate --dry-run` / `hive db migrate --dry-run` 所需的最小 CLI 代码。

禁止：改状态机、协议、迁移 SQL；接入自动更新、代码签名、云发布或付费服务；删除用户数据。

## 交付

1. **版本单一来源**：workspace 版本号一处修改；`hive --version` 与发布包文件名一致。
2. **发布包**：`cargo build --release -p hive-cli -p hive-server`，产出 zip 包含两个 exe、默认配置、`docs/RELEASE.md` 摘要与校验和（SHA256）。
3. **安装**：`scripts/install.ps1 -TargetDir <dir>` 只复制文件，不静默改 PATH、不写注册表；安装后 `hive doctor` 通过。
4. **配置兼容**：新增字段有默认值；未知字段报清晰错误；`hive config migrate --dry-run` 只打印将变更项，不改文件。
5. **数据库迁移**：启动时按 V1..Vn 顺序迁移；提供 `--dry-run` 打开数据库副本并报告版本与将执行的迁移；失败自动保留备份路径。
6. **回滚**：发布前复制 `hive.db` 为 `hive.db.bak-<version>`；回滚 = 停服 + 还原备份 + 退回复发布包；文档写清不可回滚的向前迁移。
7. **干净演练**：在 `work/h11-clean/` 安装、doctor、启动 `hive-server`、创建 Mission、读取 `/api/state`、建立 SSE 连接、停止；记录命令与输出。
8. **发布清单**：产物、版本、commit、迁移版本、已知限制、验证人。

## 完成标准

- `pwsh -NoProfile -File scripts/verify.ps1` 全绿。
- 干净目录演练全流程成功，证据落 `docs/RELEASE.md`。

## H11a 实测（配置与迁移基础）

基线：`20bd9a5`。本段单独提交，commit hash 见最终 handoff。

### 改动

- `hive-config`：新增无依赖 `.env` 解析，支持注释、空行、`KEY=VALUE`、`export KEY=VALUE`、单/双引号与 UTF-8 BOM；优先级为进程环境变量 > `.env` > 内置默认值。`.env` 中未知 `HIVE_*` 返回字段名与行号，非 `HIVE_*` 忽略；API Key 只以 set/unset 暴露。
- `hive-cli`：新增 `hive config migrate --dry-run [--file <path>]` 与 `hive db migrate --dry-run [--db <path>]`。配置 dry-run 不写文件、不改环境；数据库 dry-run 使用 `VACUUM INTO` 一致副本并在副本上迁移，原库不变。
- `hive-store`：新增只读 `read_schema_version`、`backup_database` 与 `dry_run_migration`，不改迁移 SQL、schema 或状态机。
- `hive-server`：启动前读取 `user_version`；旧库先备份到 `<data_dir>/backups/hive.db.bak-v<current>-<timestamp>`，备份失败拒绝启动；未来版本直接拒绝；当前版本不备份。
- `doctor` 语义变化：exit 0 只要求配置可加载、数据/沙箱目录可创建可写；`rustc`/`cargo` 标记为 `[optional]`，缺失不再导致失败。配置非法或目录不可写仍 exit 1。
