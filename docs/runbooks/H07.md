## 实现要点

- `wire.rs`：所有响应类型不 `deny_unknown_fields`，缺字段用 `Option`/`Default`；`Role` 与 `FinishReason` 的未知字符串降级为 `Unknown(String)`，不会解析失败。
- `sse.rs`：按字节缓冲，支持 `\n`、`\r\n`、`\r`、跨 feed 的 CRLF、跨 feed 的 UTF-8 多字节字符、多行 `data:`、注释行与 `[DONE]`；`finish()` 处理无尾随空行的最后一帧。
- `accumulate.rs`：`StreamAccumulator`（别名 `ToolCallAccumulator`）按 `index` 分桶；`id`/`name` 只取首个非空值，`arguments` 逐块 `push_str`；结束后二次 `serde_json::from_str`。
- `catalog.rs`：`/v1/models` 既可解析对象结构，也接受裸数组；`require()` 返回 `LlmError::UnknownModel`；`supports_tools` / `supports_reasoning_level` / `context_length` / `max_output_tokens` 为能力查询入口。
- `retry.rs`：纯函数 `classify(attempt, status, kind)`。429/408/5xx/传输/超时可重试；其余 4xx、取消、截断参数、已中断流不重试；`max_retries=3`（最多 4 次），`base=500ms`、指数退避、上限 `10s`。`attempt` 显式传入以保持纯函数与可测性。
- `transport.rs`：`ChatTransport` 是阻塞式注入点；`MockTransport` 可脚本化状态码、错误体、传输失败和任意 SSE 分块；`collect_stream` 组合解析器与累加器。
- `gateway.rs`：最小同步重试循环，仅供本阶段验证；真实 HTTP、异步取消与 `Retry-After` 处理留给 H04。

## 验收对照

- fake server 覆盖 400、401、429、500、断流、空内容、截断和工具调用：本阶段以 `MockTransport` 覆盖 400/429/500（重试分类）、传输中断、空参数、截断参数与工具调用；401 走同一 4xx 分支，未单独造 fake HTTP server。
- 所有重试可取消、尊重退避并有上限：策略与上限已实现并测试；“可取消”需 H04 的异步适配器接入 `CancellationToken`，本阶段未实现。
- 路由失败不会静默换模型；fallback 产生事件：本阶段不实现路由与事件，`UnknownModel` 显式报错，不自动换模型。
- API Key 不出现在日志、事件、错误和配置输出中：本 crate 不接收、不存储、不输出 key；错误体截断到 2048 字符，仅保留服务端 `message`/原始 body。

## 遗留风险

1. 真实 HTTP 适配器缺失：`ChatTransport` 只有 mock 实现，H04 接入前无法对 Magpie 发起实际请求。
2. 同步重试的 `thread::sleep` 不可取消：H04 必须改为 async + 取消令牌；当前实现仅作策略验证。
3. 退避无抖动：`RetryPolicy` 为确定性纯函数，未加 jitter；多并发客户端可能同步重试。
4. SSE 行缓冲无硬上限：上游若持续发送无换行数据会增长内存，接入真实传输时需加行/帧上限。
5. token 估算为 `len/4` 粗估：流式预算只能先估算、末块校准，精确 tokenizer 未接入。
6. `401` 响应体与 `429/5xx` 真实结构仍未实测，分类依赖状态码，错误体仅作诊断。
