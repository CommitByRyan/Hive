# H09a — 预算账本与启动恢复

> 状态：ready after H06b/H08 merge；基线以合并后 main 为准
> 依据：`docs/design/H09-recovery-observability.md` §2/§4、`docs/ADR/0005-budget-routine-recovery.md` D2–D4/D6

## 目标

落 V5 预算账本，让 Node 在 token/cost/requests/tool_calls 超限时结构化失败；落启动恢复扫描，保证旧租约、孤儿审批和不确定副作用按 fail-closed 处置，不重复执行副作用。

## 允许范围

- `crates/hive-types`：`NodeState` 增加 `waiting_approval -> needs_recovery`；`EventKind::NodeNeedsRecovery`（`node.needs_recovery`）及 round-trip 测试。
- `crates/hive-store`：V5 `budgets` 迁移、原子扣减、事实表幂等、恢复/审批辅助方法；不得改 V1–V4 SQL。
- `crates/hive-runtime`：`recovery` 模块、启动扫描顺序、预算超限后的 `failed_final`/下游 skip。
- `crates/hive-agent`：模型请求前与工具 dispatch 前的预算预检/结算接线。
- 对应测试与 `docs/runbooks/H09a.md` 实测结果。

禁止：Routine/V6、`hive-server` 路由、session 续跑、自动重放已 `started` 的副作用、修改 `PROTOCOL.md`/`WHITEBOARD.md`/ADR。

## 交付

1. **V5 `budgets`**：按设计 §2.3 建表；`SCHEMA_VERSION=5`；验收 `fresh -> V5` 与 `V4 -> V5` 数据保留；V1–V4 原样重跑。
2. **预算语义**：`tokens`/`cost`/`requests`/`tool_calls` 硬上限；`wall_ms` 默认只告警；可选 `max_wall_ms` 仅在当前 attempt 无 `started` 副作用时强停。
3. **原子扣减**：`UPDATE ... WHERE consumed + delta <= hard_limit` 与 usage/tool_call 事实行同事务；`request_id` 幂等，网关内部重试不重复计费；usage 缺失写 `estimated >= 1`。
4. **超限**：发 `node.budget_exceeded`，Node 直接 `failed_final`，不发 `node.ready`、不自动重试；下游按既有 `skip_downstream`。
5. **恢复扫描**：`revoke_all_active_leases`（`leased->ready` 发 `node.ready`；`running->needs_recovery` 发 `node.needs_recovery`）→ `expire_overdue_approvals` → 副作用分级 → 孤儿审批 → `retry_ready` 防御归位；每步 CAS/幂等。
6. **孤儿审批**：pending/approved-未消费审批置 `expired`（`decided_by=recovery`、`decision_note=owner_lost`）；无 `started` 副作用走 `failed -> retry_ready -> ready`；已有副作用走 `needs_recovery`；不重装 session。
7. **重建**：`rebuild_budget_counters` 从事实表重算，幂等；历史 `budget_exceeded` 节点保持 `failed_final`。
8. 测试覆盖设计 §2.7 的 7 条与 §4.5 的 8 条；新增 `waiting_approval` 三分支与 `node.needs_recovery` 同事务断言。
