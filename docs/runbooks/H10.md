## 交付

### 1. 固定场景集（`hive-eval`）

| 场景 | 内容 | 断言 |
|---|---|---|
| `s1-single` | 单 Mission / 单 Node / MockTransport 一次完成 | 事件顺序 `node.ready -> node.started -> node.succeeded`，1 条 handoff |
| `s2-dag` | 1 入口 → 8 并行 → 1 汇合，`max_parallel=4` | 8 节点全部成功；并行段墙钟显著低于串行上界；无重复 `node.started` |
| `s3-handoff` | 3 段链式 Handoff，后一段读取前一段 handoff | 每段 `handoff.created` 唯一、`base_revision` 可追溯；无整段对话倾倒 |
| `s4-retry` | 首 attempt 500 retryable，次 attempt 成功 | 恰好一条 `node.failed`，attempt 只递增一次，最终 succeeded |
| `s5-budget` | token 上限触发（H09a 合并后启用） | `node.budget_exceeded` + `failed_final`，无自动重试，下游 skip |
| `s6-cancel` | 运行中取消 Mission | 未终态节点 `cancelled`，无新 `node.tool_started`，进程退出后重启恢复扫描不重放 |

每个场景必须支持 `--out <path.jsonl>` 与 `--runs <n>`，输出稳定 schema：

```json
{"scenario":"s2-dag","commit":"<sha>","run":1,"workers":4,"nodes":10,"wall_ms":123,"events":42,"db_bytes":40960,"ok":true}
```

### 2. 确定性 fake

- `ScriptedTransport`：按请求序号返回预设 200/429/500/超时/畸形 JSON，不访问网络。
- `ScriptedToolExecutor`：返回成功、策略拒绝、执行失败、悬挂后取消四类结果。
- 所有 fake 必须线程安全、可被多个 worker 共享；不得依赖真实 Magpie。

### 3. 故障注入矩阵

| 故障 | 注入方式 | 期望 |
|---|---|---|
| 模型 429/5xx | ScriptedTransport | 有界重试；耗尽后 `failed`，事件不重复 |
| 模型超时 | transport 返回超时错误 | 可重试；取消后立即停止下一轮 |
| 工具策略拒绝 | dispatcher 返回 denied | `node.tool_result` 记录拒绝原因，不执行副作用 |
| 工具执行失败 | fake executor 返回 error | 节点按 retryable 规则处理 |
| 数据库锁 | 第二连接持写事务，主连接写事件 | `busy_timeout` 内成功或结构化失败，不丢事件 |
| 强杀恢复 | 子进程执行中 `Stop-Process -Force` 后重启扫描 | 已 `started` 无终态 → `needs_recovery`，不自动重放 |
| 磁盘慢写 | 可选：大事件 payload 压测 | 报告写放大与失败率，不设硬性阈值 |

每个故障至少一条自动化测试；强杀场景用独立进程 + 临时 DB，测试结束清理。

### 4. 指标与报告

- 指标：`wall_ms`、`events/sec`、节点 p50/p95 完成时间、峰值并行度、DB 增长、重试次数、取消延迟。
- 每次测量：先 1 次预热，再至少 5 次采样，报告 median 与 p95；禁止用单次运行下结论。
- 必须记录：CPU、内存、磁盘类型、OS、Rust 版本、commit、`max_parallel`、样本量。
- 报告落 `docs/audits/H10-benchmark-report.md`，含原始 JSONL 路径与复现命令。
- 只有在能找到 Python 原型源码并同等条件运行时才写对比；否则写“不可比及原因”。

### 5. 安全回归

复用既有策略测试并补三条端到端断言：`shell.enabled=false` 时零进程创建；路径逃逸在 dispatcher 层被拒；未审批的高风险工具不产生 `node.tool_started`。
