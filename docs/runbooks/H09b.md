# H09b — Routine 定时触发

> 状态：ready after H08 + H09a merge；基线以合并后 main 为准
> 依据：`docs/design/H09-recovery-observability.md` §3、`docs/ADR/0005-budget-routine-recovery.md` D1/D8/D10/D11

## 目标

落 V6 `routines`/`routine_fires`、`rt_` 公开 ID、四个 Routine 事件、创建期表达式校验、同窗口幂等触发、重启 skip-missed，以及与 H08 对齐的 `/api/routines` 路由。

## 允许范围

- `crates/hive-types`：`RoutineId`（`rt_`）、`ID_PREFIXES` 扩到 13、`EventKind::{RoutineTriggered,RoutineError,RoutineUpdated,RoutineDeleted}`。
- `crates/hive-store`：V6 迁移、Routine CRUD、到期领取、幂等 fire；不得改 V1–V5 SQL。
- `crates/hive-runtime`：Routine tick 循环（one bad row 不拖垮循环）。
- `crates/hive-server`：`GET/POST /api/routines`、`POST/DELETE /api/routines/{id}`。
- 对应测试与 `docs/runbooks/H09b.md` 实测结果。

禁止：新增 `missions.source` 列；改 H08 已实现路由语义；引入 `tracing`/`metrics`；改 PROTOCOL/WHITEBOARD/ADR。

## 交付

1. **V6 schema**：按设计 §3.3 建 `routines` 与 `routine_fires`；`SCHEMA_VERSION=6`；验收 `fresh -> V6` 与 `V5 -> V6` 数据保留；V1–V5 原样重跑。
2. **ID/事件**：`RoutineId` 前缀 `rt_`；四个 `routine.*` 事件 round-trip；`node_id/attempt_no` 为 null。
3. **表达式**：`every:<N>m|h`（5m–7d）、`hourly`、`daily:HH:MM`；创建期解析并算首个 `next_run_ms`；非法 `400 invalid_schedule`；单文件被改坏时 tick 只停用该行并发 `routine.error`。
4. **幂等触发**：`(routine_id, fire_at_ms)` 主键 + `next_run_ms` CAS；同一事务建 Mission、写 `routine_fires`、发 `routine.triggered`；失败记 `failed` + `routine.error`，不自动重放。
5. **重启**：skip-missed，只触发下一个到期窗口；时区固定 `Asia/Shanghai`，其他值 `400 invalid_timezone`；`daily` 按 UTC+8 换算（中国无 DST，优先固定偏移 + civil date，避免新依赖）。
6. **API**：GET 列表、POST 创建（上限 50，`400 routine_limit`）、POST `{id}` 更新、DELETE `{id}`；响应字段严格按设计 §3.5。
7. 测试覆盖设计 §3.6 的 6 条 + API 错误码 + `V5 -> V6` 迁移。
