# H13 — worktree 回收的脏数据安全

> 状态：ready after H11；H06d-1 遗留的数据丢失风险。
> 输入：`crates/hive-workspace/src/lib.rs`、`docs/runbooks/H06d.md`、H06d-1 handoff。
> 原则：默认不销毁未提交工作；显式选择才允许强删。

## 目标

把 `WorktreeManager::recycle` 的默认行为从“脏 worktree 直接强删”改为“默认保留、显式才强删”，并补足可验证测试与文档。

## 允许范围

- `crates/hive-workspace` 的 `RecyclePolicy`/`recycle` 与测试。
- `docs/runbooks/H13.md`、`docs/runbooks/H06d.md` 的补充说明。

禁止：改 Git 历史、改 worktree 创建/合并语义、删除用户数据、push/建远端。

## 交付

1. `RecyclePolicy` 的默认值改为 `keep_dirty: true`；显式 `keep_dirty: false` 才允许对脏 worktree 走 `git worktree remove --force`。
2. `recycle` 的文档注释与 runbook 明确：默认保留脏 worktree，返回 `KeptDirty`；强删是破坏性操作，必须由调用方显式选择。
3. 测试：
   - 默认策略遇到 dirty → 保留、内容仍在、返回 `KeptDirty`；
   - 显式 `keep_dirty: false` → 删除、返回 `Removed`；
   - 非 dirty 默认 → 正常删除；
   - 现有 `remove` 的 force 语义不回归。
4. 搜索所有 `RecyclePolicy` 构造点：如果有服务/CLI 路径依赖默认强删，改为显式 `keep_dirty: false` 并在文档标注风险；没有则说明。
5. `pwsh -NoProfile -File scripts/verify.ps1` 全绿，记录数字与命令。

## 完成标准

- 默认路径不可能在无提示下删除未提交 worktree。
- 测试覆盖默认保留与显式强删两条路径。
- 不改变创建、合并、预览行为。

## 模型

- 主写：`auto/deepseek-v4.1-flash` high。
