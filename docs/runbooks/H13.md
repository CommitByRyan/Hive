# H13 — worktree 回收的脏数据安全

> 状态：done；H06d-1 遗留的数据丢失风险已关闭。
> 输入：`crates/hive-workspace/src/lib.rs`、`docs/runbooks/H06d.md`、H06d-1 handoff。
> 原则：默认不销毁未提交工作；显式选择才允许强删。

## 目标

把 `WorktreeManager::recycle` 的默认行为从“脏 worktree 直接强删”改为“默认保留、显式才强删”，并补足可验证测试与文档。

## 允许范围

- `crates/hive-workspace` 的 `RecyclePolicy`/`recycle` 与测试。
- `docs/runbooks/H13.md`、`docs/runbooks/H06d.md` 的补充说明。

禁止：改 Git 历史、改 worktree 创建/合并语义、删除用户数据、push/建远端。

## 交付

1. `RecyclePolicy` 的默认值改为 `keep_dirty: true`；显式 `keep_dirty: false` 才允许对脏 worktree 走 `git worktree remove --force`。
2. `recycle` 的文档注释与 runbook 明确：默认保留脏 worktree，返回 `KeptDirty`；强删是破坏性操作，必须由调用方显式选择。
3. 测试：
   - 默认策略遇到 dirty → 保留、内容仍在、返回 `KeptDirty`；
   - 显式 `keep_dirty: false` → 删除、返回 `Removed`；
   - 非 dirty 默认 → 正常删除；
   - 现有 `remove` 的 force 语义不回归。
4. 搜索所有 `RecyclePolicy` 构造点：如果有服务/CLI 路径依赖默认强删，改为显式 `keep_dirty: false` 并在文档标注风险；没有则说明。
5. `pwsh -NoProfile -File scripts/verify.ps1` 全绿，记录数字与命令。

默认策略实现为手写 `impl Default for RecyclePolicy`，返回 `keep_dirty: true`；未使用 derive 的 `false`。
`recycle` 行为：脏 worktree + 默认 → `KeptDirty`；脏 + 显式 `keep_dirty: false` → `git worktree remove --force` 后 `Removed`；干净 + 默认 → `Removed`。

`hive-workspace` 测试 **13 passed / 0 failed**（既有 10 条不退化，本轮 +3）：

- `recycle_policy_default_keeps_dirty_worktree`：默认策略保留脏 worktree，目录、未跟踪文件与已修改文件内容仍在，`git status` 仍为 dirty，worktree 仍在 `list()` 中。
- `recycle_default_policy_removes_clean_worktree`：干净 worktree 用默认策略正常删除并返回 `Removed`。
- `recycle_explicit_force_removes_dirty_worktree`：显式 `keep_dirty: false` 强删脏 worktree，目录消失。

既有 `remove_rejects_dirty_worktree_without_force` 仍覆盖非 force 拒绝脏 worktree、force 才删除，未回归。
全仓数字见下方验证记录（提交前 `verify.ps1` 输出）。

生产路径核查：全仓 `RecyclePolicy` 构造点仅存在于 `crates/hive-workspace/src/lib.rs` 的测试中；
`recycle(` 无任何服务/CLI/Agent 生产调用（`hive-agent` 只调用 `head_revision_at`），因此没有依赖“默认强删”的生产路径需要改成显式 `keep_dirty: false`。
