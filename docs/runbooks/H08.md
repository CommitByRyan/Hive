# H08 — 服务与 Web

> 状态：design ready；实现等待 H06 合并（避免 `hive-store` / `hive-types` 写冲突）
> 设计：`docs/design/H08-http-console.md`，其中 §1 的 11 条路由是本轮唯一接口清单

## 目标

在不成为状态所有者的前提下，交付本地 HTTP/SSE 服务边界与最小 Web 控制台：快照 + `seq` 补偿、审批操作、DAG/事件/产物视图。

## 允许范围

- 新建 `crates/hive-server` 与根 `Cargo.toml` member。
- `crates/hive-server/web/`（或 crate 内静态资源目录）：最小控制台。
- `crates/hive-store`：只允许**追加只读查询方法**（如 `list_missions`、`list_artifacts`、Mission 详情所需读取）；不得改 V1–V4 schema、迁移、事件封套、公共状态枚举。
- `docs/runbooks/H08.md` 的实测结果。
- 新依赖仅限 `axum` + `tokio`；静态资源用内置 fallback，不引 `tower-http`。如需额外依赖，先在 handoff 说明理由，不擅自扩大。

## 交付

1. `hive-server`：配置（默认仅 `127.0.0.1`）、路由、统一错误体、请求大小/Origin/Content-Type 校验、静态控制台。
2. 路由严格按设计 §1 的 11 条；`/api/health` 的 `schema_version` 读 `hive_store::SCHEMA_VERSION`，另给 `event_schema_version`，禁止硬编码。
3. SSE 按设计 §2：先持久补偿再实时；`Last-Event-ID` 优先；单连接 256 队列、慢客户端丢最旧并发送 `hive.lagged`；不得阻塞事件提交或 SQLite 写事务。
4. 审批按设计 §4：原子 decide、过期/重复决定稳定错误码、决定与执行结果分开呈现。
5. 最小控制台：Mission 列表/创建、详情 DAG、事件流、审批面板、产物列表；只读投影，不整页轮询。
6. 验收测试按设计 §7 的 16 条落地；至少覆盖持久补偿、lag、并发审批、非法游标、恶意 Origin、413。

## 禁止

- HTTP 层直接写 SQL 或成为状态权威；不得绕过 `Store` / `EventBus`。
- 返回 API Key、base URL、Cookie、环境变量或完整模型清单。
- 改冻结协议、V1–V4 迁移 SQL、`WHITEBOARD.md`；不 push。

## 完成标准

- `pwsh -NoProfile -File scripts/verify.ps1` 全绿，既有测试不退化。
- `cargo run -p hive-server` 能启动并返回 `/api/health`；控制台可用真实 SSE 连接。
- handoff 写真实命令、端口、测试数字与未覆盖项。
- 模型：`auto/glm-5.3` 主写；SSE 并发与审批竞态段由 H00 用 `auto/deepseek-v4-pro` high 复核。
