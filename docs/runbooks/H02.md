# H02 — 持久化与事件

> 状态：implemented, verified
> 基线：H01 已验证通过；本阶段未 commit / push

## 目标

实现 SQLite 迁移、Mission/Run/Node/Event 基础表、事务写入、事件游标、快照与重启恢复。

## 冻结点

- 状态转移与初始事件同事务。
- `seq` 单调递增且可补齐；`event_id` 唯一并用于幂等。
- 租约与 attempt 不覆盖历史。
- 大输出分段存储，不塞满事件行。

## 交付

- schema 与迁移。
- store/event repository 与事务 API。
- 断线补偿和崩溃恢复测试。
- 明确的并发写策略与锁边界。

### schema 与迁移

- `hive_store::SCHEMA_VERSION` 是数据库版本唯一来源；迁移按 `user_version` 逐步循环，每步独立事务，版本高于代码支持时直接报错。
- V1 表：`missions`、`runs`、`nodes`、`events`、`snapshots`、`approvals`。
- 打开连接即设置 WAL、`foreign_keys=ON`、`busy_timeout=5000`。
- `nodes` 独立保存 `attempt_no`、`lease_token`、`lease_expires_at_ms`、`retry_budget`，attempt 与 lease 不混用。
- `events` 使用 `seq INTEGER PRIMARY KEY AUTOINCREMENT` 作为游标、`event_id TEXT UNIQUE` 作为稳定身份；持久化封套不含 `agent`，`run_id/node_id/session_id` 可空。
- `snapshots` 使用 `last_seq` 与 `schema_version` 列。
- `approvals` 已按 H03 契约预置：唯一 `tool_call_id`、`state` 检查约束、待决过期索引；`tool_calls` 与审计哈希链留给 H03 的 V2。

### 事务与恢复策略

- 所有“状态更新 + 事件”入口在同一事务内提交：`transition_node_and_emit`、`transition_node_cas`、`transition_node_and_request_approval`、审批决策、回收等。
- 写事务使用 `TransactionBehavior::Immediate`，单写者串行化；读不受阻塞（WAL）。
- `seq` 上界 `MAX_SEQ = 2^53 - 1`；分配与读取入参都校验，超限返回 `StoreError::SequenceExhausted`，写 SQLite 前做 `i64::try_from`。
- `event_id` 重复提交返回幂等失败，不产生第二条记录。
- `retry_budget` 是首次之后的额外次数（默认 3，最多 4 次 attempt）；`can_retry(attempt_no, retry_budget) = attempt_no <= retry_budget`。
- `attempt_no` 只在下一次领取并开始执行时递增，失败时不递增；`retry_node` 是恢复路径的显式递增入口。
- 租约回收：`leased` 过期 → `ready`（attempt 不变）；`running` 过期 → `needs_recovery`（人工 `retry_node` 才递增 attempt，`abort_node` → `failed_final`）。
- 旧 `LeaseGuard`（attempt 或 token 任一不匹配）返回 `StoreError::StaleExecution`，不能续租或写事件。

### 快照语义

快照是物化状态缓存，不是权威数据，也不做事件压缩。恢复时 `schema_version`、作用域（mission/run/node/kind）、`last_seq` 任一不符即弃用并按事件重建。

### 事件桥接

- `hive-events` 不依赖 Tokio；每个订阅者独立有界队列。
- 队列满时丢弃最旧事件并累加 `lagged`，写事务与 `publish` 都不会被慢订阅者阻塞。
- 订阅者可按 `MissionFilter::Mission` 过滤；提供 `try_recv` 与 `recv_timeout`。
- `append_and_publish` 先持久化成功，再广播。
