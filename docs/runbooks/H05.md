# H05 — 并行 DAG 调度

> 状态：implemented, verified（P0 完成并提交；线程化执行器留 H05b）

## 目标

实现真正并行的 DAG 调度、ready queue、租约、重试、取消传播和分支失败。本轮交付的是**确定性调度状态机**（actor/step 风格），不做线程池；并发语义在无网络、无线程的测试里精确驱动，线程化执行器留 H05b。

## 交付内容

### CancellationToken 下沉到 `hive-types`

- 从 `hive-agent` 移到 `hive-types`（纯 std，无新依赖）。
- 新增 `CancellationToken::child()` 父/子级联：父取消级联到子，子取消不影响父。
- `hive-agent` 用 `pub use hive_types::CancellationToken` 重导出，保持兼容。

### 新建 `crates/hive-runtime`

- `Plan` / `PlanNode` / `NodeSpec`：`PlanNode { node_id, deps, spec, retry_budget }`。
- `validate_plan(&Plan) -> Result<Topology, PlanError>`：重复 ID、自依赖、缺失依赖、环、空计划；Kahn 算法返回确定性拓扑序。
- `NodeExecutor` trait 与 `ExecOutcome { Succeeded | Failed { retryable } | Cancelled }`。
- `Scheduler<S: StoreLike>`：`new(topology, max_parallel, cancel, store)` / `next_actions()` / `on_started(node)` / `on_finished(node, outcome)` / `cancel()`。
  - `next_actions()` 返回 `Start(node)` / `Wait` / `Halt`，在飞节点数（offered + running）不超过 `max_parallel`。
  - `on_started` 先租约（`ready -> leased`）再 `leased -> running` + `node.started`，全程带 `LeaseGuard`。
  - 依赖满足才 ready；失败节点 `can_retry` 为真则重入 ready 并递增 attempt，否则 `failed_final`，其下游递归 `skipped`。
  - `cancel()` 把 running/ready 全部转 `cancelled` 并触发共享 token，不再发 `Start`。
- 事件：`plan.created`、`node.ready`、`node.started`、`node.succeeded`、`node.failed`、`node.cancelled`、`node.skipped`，全部走 `StoreLike`（即 store 的 CAS/guarded 入口），runtime 不直接发 SQL `UPDATE`。

### `hive-store` 加法式方法（不改 schema/事件/状态枚举）

- `add_node_with_id(node_id, ...)`：按计划里的确切 `node_id` 落库（原 `add_node` 改为其包装）。
- `retry_failed_node(node_id, now_ms)`：`failed -> retry_ready -> ready`，attempt + 1、清租约，单事务。
- `abort_failed_node(node_id, now_ms)`：`failed -> failed_final`，清租约，单事务。

三者与既有 `retry_node` / `abort_node` 对齐，均不改变 V1 schema、事件封套或公共状态枚举。

## 验收

- 无依赖节点并行；有依赖节点严格等待（菱形 DAG 测试）。
- `max_parallel` 从未被超过（fan-out 测试逐批断言）。
- 单节点失败只 skip 其下游，不阻塞兄弟分支。
- 重试：budget=3 时第 4 次失败进 `failed_final`（4 条 `node.failed`）。
- 取消：running 与 ready 都变 `cancelled`，之后不再发 `Start`。
- 父 token 取消级联到子 token。
- 事件序列与最终 Node 状态一致。
- 环/重复 ID/缺失依赖/自依赖/空计划分别报对应错误。
- 同一节点不会重复 Start。
