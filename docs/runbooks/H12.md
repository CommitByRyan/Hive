# H12 — 保留水位持久化与自动归档

> 状态：ready after H11；H09c 遗留的真实正确性缺口。
> 输入：`docs/design/H09-recovery-observability.md` §5、`docs/audits/H10-benchmark-report.md`、`WHITEBOARD.md`、H09c runbook。
> 原则：宁可让客户端多取一次快照，也不得让已归档事件静默消失；先持久化水位，再删行。

## 目标

修复 `retained_since_seq` 只存在进程内、重启后回到 0 的问题；并把终态 Mission 归档接入启动与周期生命周期，使长期运行的服务也能自动保留/清理。

## 允许范围

- `crates/hive-store`：保留水位 sidecar 持久化、归档顺序收紧、测试；不改 V1–V6 schema、不改迁移 SQL。
- `crates/hive-runtime`：启动/周期归档接线与测试。
- `crates/hive-server`：配置接线与只读暴露；不改变 H08 冻结字段语义。
- `crates/hive-config`：新增 `HIVE_RETENTION_DAYS`、`HIVE_ARCHIVE_DIR`，必须有默认值。
- `docs/runbooks/H12.md` 实测记录。

禁止：改 V1–V6 schema、PROTOCOL/ADR/WHITEBOARD、事件格式；删除活跃 Mission 事件；新增外部 crate；push/建远端。

## 交付

### H12a — 保留水位持久化（commit 1：`feat: H12a 保留水位持久化`）

1. **sidecar 文件**：`<data_dir>/retention.json`，内容 `{"retained_since_seq": <u64>}`；`Store::open(path)` 时加载，`open_in_memory()` 不持久化。
2. **写入顺序**：归档时先计算新 floor，原子写 sidecar（临时文件 + `sync_all` + 替换），成功后才在同一事务删除 `events/tool_audit/snapshots`。sidecar 写失败 → 不删行、返回错误；删除失败 → floor 已前移，客户端最多多重取快照，允许。
3. **损坏处理**：sidecar JSON 非法/版本字段异常 → `Store::open` 返回清晰错误并拒绝启动；runbook 写恢复步骤（确认归档文件后修复/删除 sidecar）。不得静默重置为 0。
4. **重启语义**：归档后 drop Store、重新 open，`retained_since_seq()` 仍为归档后的值；`/api/events?after_seq=0` 在重启后仍返回 409 `snapshot_required`。
5. **测试**：正常持久化、重启保留、损坏 sidecar 拒绝、sidecar 写失败不删行、活跃 Mission 不受影响。

### H12b — 自动归档（commit 2：`feat: H12b 自动归档`）

6. **配置**：`HIVE_RETENTION_DAYS` 默认 `30`，`0` 表示关闭自动归档；`HIVE_ARCHIVE_DIR` 默认 `<data_dir>/archive`。非法值返回配置错误。
7. **启动归档**：`run_startup` 在恢复/预算重建之后执行一次 `archive_expired_missions`（可关闭）；失败不得阻止恢复完成，但必须记录错误并保持原数据。
8. **周期归档**：server 启动一个可停止的低频循环（建议 1 小时，不与 1s tick 混在一起），重复执行也必须幂等；`Drop`/shutdown 停止。
9. **健康/状态**：`/api/health` 的 `retained_since_seq` 在重启后仍正确；归档失败可通过日志/指标观测，不误报 `degraded` 为 5xx。
10. **测试**：启动归档、周期归档幂等、`RETENTION_DAYS=0` 不归档、归档目录不可写时不删行、重启水位保留。

### sidecar 形状与写入顺序

sidecar 位于数据库同目录：`<hive.db 的父目录>/retention.json`。`Store::open_in_memory()` 不创建、不读取 sidecar，水位仍为进程内 0。

```json
{"retained_since_seq":3}
```

- 启动加载：文件不存在 → 0；JSON 非法、缺字段、负数或 `> MAX_SEQ` → `Store::open` 返回 `retention_error`，消息包含 sidecar 绝对路径，**不静默重置**。
- 写入：先写同目录临时文件 `.retention.json.hive-tmp-<pid>`，`sync_all` 后用 `std::fs::rename` 替换。Windows 下 `rename` 走 `MoveFileExW(REPLACE_EXISTING)`，同一卷内为替换语义。
- 归档顺序：写归档 `events.jsonl` 并 `sync_all` → 计算 `boundary = max(archived seq + 1)` 与新 floor → 持久化 sidecar → 更新内存 floor → 同一事务删除 `events/tool_audit/snapshots`。
- 失败语义：sidecar 写失败时 floor 与行都不变；删除事务失败时 floor 已前移，客户端最多多重取一次快照，不会静默丢事件。
- 幂等：`archive_expired_missions_with_days` 只选择仍拥有 `events`/`tool_audit`/`snapshots` 的终态 Mission；整段删除后再次扫描不会重复归档。

### 配置与生命周期

- `HIVE_RETENTION_DAYS`：默认 `30`；非负整数；`0` 关闭自动归档（启动与周期都不调用归档）。非法值使 `Config::load` 失败。
- `HIVE_ARCHIVE_DIR`：默认 `data/archive`（相对项目根，沿用 `validated_path` 规则）；可写绝对或相对路径。
- `run_startup_with_retention`：恢复扫描与预算重建之后执行一次归档；归档失败只写入 `StartupReport.retention_error`，恢复结果仍返回，server 继续启动并打印 stderr。
- server 周期：`RETENTION_PERIOD = 3600s`，与 1s tick 分离；每轮锁 store 调 `retention_once`，失败只打印 `retention archive failed: ...`，不退出进程。
- `AppState` shutdown 修正：只有 `AppState::new` 创建的 owner 在 `Drop` 时置位；请求/路由 clone 不再提前停止 tick 与 retention 循环。

### 损坏 sidecar 的恢复步骤

1. 先确认 `data/archive/<mission_id>/events.jsonl` 已完整落盘（首行 header 的 `event_count` 与后续行数一致）。
2. 停止 server，备份 `retention.json`。
3. 若归档完整，可把 `retention.json` 修正为 `{"retained_since_seq":<已归档最大 seq + 1>}`；若没有可靠水位，删除 sidecar 会让 floor 回到 0，此时必须确认对应事件行仍存在，否则客户端会出现静默缺口。
4. 重新启动后检查 `/api/health` 的 `retained_since_seq` 与 `/api/events?after_seq=0` 的 409 响应。

### 残余风险

- 归档文件按追加方式写；sidecar 持久化失败后重试会再次追加同一 Mission 的 header 与事件。行未丢，但归档文件需要按 header 分段读取。
- sidecar 只原子替换文件内容，未对父目录做额外 fsync；掉电窗口内依赖 NTFS/文件系统语义。
- 归档失败时 `archive_expired_missions_with_days` 在第一个失败 Mission 处返回错误；后续 Mission 留待下一次启动/周期重试，不会出现“删了但 floor 未持久化”。
- 保留阈值严格 `<`：`updated_at_ms == now_ms - days*86400000` 不归档。
