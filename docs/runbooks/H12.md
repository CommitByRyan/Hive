# H12 — 保留水位持久化与自动归档

> 状态：ready after H11；H09c 遗留的真实正确性缺口。
> 输入：`docs/design/H09-recovery-observability.md` §5、`docs/audits/H10-benchmark-report.md`、`WHITEBOARD.md`、H09c runbook。
> 原则：宁可让客户端多取一次快照，也不得让已归档事件静默消失；先持久化水位，再删行。

## 目标

修复 `retained_since_seq` 只存在进程内、重启后回到 0 的问题；并把终态 Mission 归档接入启动与周期生命周期，使长期运行的服务也能自动保留/清理。

## 允许范围

- `crates/hive-store`：保留水位 sidecar 持久化、归档顺序收紧、测试；不改 V1–V6 schema、不改迁移 SQL。
- `crates/hive-runtime`：启动/周期归档接线与测试。
- `crates/hive-server`：配置接线与只读暴露；不改变 H08 冻结字段语义。
- `crates/hive-config`：新增 `HIVE_RETENTION_DAYS`、`HIVE_ARCHIVE_DIR`，必须有默认值。
- `docs/runbooks/H12.md` 实测记录。

禁止：改 V1–V6 schema、PROTOCOL/ADR/WHITEBOARD、事件格式；删除活跃 Mission 事件；新增外部 crate；push/建远端。

## 交付

### H12a — 保留水位持久化（commit 1：`feat: H12a 保留水位持久化`）

1. **sidecar 文件**：`<data_dir>/retention.json`，内容 `{"retained_since_seq": <u64>}`；`Store::open(path)` 时加载，`open_in_memory()` 不持久化。
2. **写入顺序**：归档时先计算新 floor，原子写 sidecar（临时文件 + `sync_all` + 替换），成功后才在同一事务删除 `events/tool_audit/snapshots`。sidecar 写失败 → 不删行、返回错误；删除失败 → floor 已前移，客户端最多多重取快照，允许。
3. **损坏处理**：sidecar JSON 非法/版本字段异常 → `Store::open` 返回清晰错误并拒绝启动；runbook 写恢复步骤（确认归档文件后修复/删除 sidecar）。不得静默重置为 0。
4. **重启语义**：归档后 drop Store、重新 open，`retained_since_seq()` 仍为归档后的值；`/api/events?after_seq=0` 在重启后仍返回 409 `snapshot_required`。
5. **测试**：正常持久化、重启保留、损坏 sidecar 拒绝、sidecar 写失败不删行、活跃 Mission 不受影响。

### H12b — 自动归档（commit 2：`feat: H12b 自动归档`）

6. **配置**：`HIVE_RETENTION_DAYS` 默认 `30`，`0` 表示关闭自动归档；`HIVE_ARCHIVE_DIR` 默认 `<data_dir>/archive`。非法值返回配置错误。
7. **启动归档**：`run_startup` 在恢复/预算重建之后执行一次 `archive_expired_missions`（可关闭）；失败不得阻止恢复完成，但必须记录错误并保持原数据。
8. **周期归档**：server 启动一个可停止的低频循环（建议 1 小时，不与 1s tick 混在一起），重复执行也必须幂等；`Drop`/shutdown 停止。
9. **健康/状态**：`/api/health` 的 `retained_since_seq` 在重启后仍正确；归档失败可通过日志/指标观测，不误报 `degraded` 为 5xx。
10. **测试**：启动归档、周期归档幂等、`RETENTION_DAYS=0` 不归档、归档目录不可写时不删行、重启水位保留。
