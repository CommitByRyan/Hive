# H06c — 真实 Agent 工作线程与 ThreadedExecutor 联调

> 状态：ready after H06b merge；基线以合并后 main 为准
> 目标：让 `ThreadedExecutor` 真正跑 `AgentRunner` 的工作节点，证明租约、Handoff、失败重试、取消在真实执行路径闭环。

## 当前障碍

`ThreadedExecutor::run` 的工厂是 `FnMut(Store) -> E`，但 `AgentRunner` 借用 `&mut Store` / `&ToolDispatcher` / `&Gateway`，无法返回一个引用工厂局部 `Store` 的执行器。H06b 的 `OverlapExecutor` 只验证 guard 传递，不是真实 Agent 闭环。

## 允许范围

- `crates/hive-agent`：新增自持有执行器（建议 `worker_executor.rs`），必要时调整可见性；不改 `run_node_with_lease` 语义。
- `crates/hive-runtime`：仅在工厂签名确实不够时做最小 API 调整；不改调度状态机语义。
- 上述 crate 的测试与 `docs/runbooks/H06c.md` 实测结果。

禁止：改 V1–V4 迁移、`PROTOCOL.md`、`WHITEBOARD.md`、公共状态枚举；不得在 worker 路径重新 `lease_node`；不引 async runtime。

## 交付

1. `WorkerAgentExecutor<T>` 自持有 `Store`、`ToolDispatcher`、`Gateway<T>`（或 `Arc` 包装），实现 `NodeExecutor`：
   - `execute(node, lease, cancel)`：建 session、构造 `AgentSpec`、调用 `run_node_with_lease`；
   - 不自行领取租约，不重复发 `node.started`。
2. 提供与 `ThreadedExecutor::run` 兼容的工厂 helper；每个 worker 独立 `Store` 连接。
3. 集成测试（真实 `ThreadedExecutor::run` + `WorkerAgentExecutor<MockTransport>`）：
   - 两个无依赖节点并行成功；Handoff 各自落库，`node.succeeded` payload 含各自 `handoff_id`；
   - lease token 互不相同，每个节点只有一条 `node.started`，attempt 只递增一次。
4. 失败/重试集成：第一次 500（retryable）→ `node.failed` 一次 → 下一次 attempt 成功；不得出现重复结算或第二个 `node.failed`。
5. 取消集成：取消 token 触发后 worker 停止，节点 `cancelled`，不产生新的工具副作用。
6. 保留 H06b 的 187 passed / 3 ignored 不退化；`pwsh -NoProfile -File scripts/verify.ps1` 全绿。

## 完成标准

- 真实 `ThreadedExecutor::run` 跑通 `WorkerAgentExecutor<MockTransport>`，测试不是仅验证 guard 传递。
- 报告中写真实命令、并发数、事件断言与测试数字；没有证据不得声称完成。
- handoff 五段：状态 / 改动文件 / 验证证据 / 遗留风险 / 建议下一步。
- 模型：`auto/deepseek-v4-pro` high；机械测试补齐可切 `auto/deepseek-v4.1-flash`。

## 实测结果

命令（worktree 内，先 `$env:HIVE_TOOLCHAIN_ROOT='D:\Downloads\24096\Documents\AAA_codex_code\Hive'`）：

```text
pwsh -NoProfile -File scripts/verify.ps1
```

结果：`All checks passed.`（fmt / clippy `-D warnings` / `cargo test --workspace` 全绿）。

测试合计 **190 passed / 3 ignored**（H06b 基线 187/3，本轮 +3）：

- `hive-agent` 20 单测无退化；新增 `tests/h06c_worker_executor.rs` 3 条真实 `ThreadedExecutor::run` + `WorkerAgentExecutor<MockTransport>` 集成测试：
  - `two_independent_nodes_succeed_in_parallel_with_distinct_handoffs_and_leases`：两个无依赖节点 `max_parallel=2` 并行成功；`summary.succeeded=2`、`attempt_no=1`、每节点恰一条 `node.started`；`list_handoffs` 两条、`node.succeeded.payload.handoff_id` 与各自 `HandoffRecord.handoff_id` 一致；调度器授予的两个 `lease_token` 互不相同。
  - `retryable_500_fails_once_then_succeeds_on_next_attempt`：单节点 `retry_budget=1`，`MockTransport` 脚本 `[500, 200]` 且 `Gateway` 用 `RetryPolicy::immediate(0)`（禁止网关内部重试，让 500 冒泡为 Node 级 retryable）；`summary.executed=2/succeeded=1/failed=1`、最终 `Succeeded`、`attempt_no=2`、恰一条 `node.failed`、两条 `node.started`。
  - `cancelling_token_stops_worker_and_marks_node_cancelled`：阻塞式 `ChatTransport`（`Mutex<Receiver>` 阻塞在 `send`，主线程 `cancel()` 后 `tx.send(())` 释放）；`summary.cancelled=1/succeeded=0`、节点 `Cancelled`、恰一条 `node.cancelled`、零条 `node.tool_started`。

关键实现：

- `hive-agent/src/worker_executor.rs`：`WorkerAgentExecutor<T>` 自持有 `Store` + `Arc<ToolDispatcher>` + `Arc<Gateway<T>>`，实现 `NodeExecutor::execute`，内部 `AgentRunner::new(...).run_for(node, lease, cancel)` 调 `run_node_with_lease`；不自行 `lease_node`、不重复发 `node.started`。提供 `WorkerAgentExecutor::factory(Arc<ToolDispatcher>, Arc<Gateway<T>>) -> impl FnMut(Store) -> Self` 与 `ThreadedExecutor::run` 兼容，每个 worker 独立 `Store` 连接。
- `node_executor.rs` 把 `run_for` / `map_outcome` 提升为 `pub(crate)` 供 worker executor 复用，不改 `run_node_with_lease` 语义。
- 未改 `ThreadedExecutor` 工厂签名，未改公共状态枚举、`PROTOCOL.md`、迁移 SQL、`WHITEBOARD.md`。
