# H06b — 调度器租约注入 NodeExecutor

> 状态：done, verified；基线 `a455175`（H06 已合并）
> 目标：消除实际执行路径中的第二次租约，让 `run_node_with_lease` 成为调度器驱动的唯一入口。

## 背景

H06 已提供 `AgentRunner::run_node_with_lease`，但 `NodeExecutor` 适配器仍调用旧的 `run_node`，后者会自行 `lease_node`。调度器在 `on_started` 已经领取并持有 `LeaseGuard`，因此实际执行路径仍存在双重租约。H06 runbook 已把该接线列为 H06b。

## 允许范围

- `crates/hive-runtime/src/{executor.rs,scheduler.rs,threaded.rs}`
- `crates/hive-agent/src/node_executor.rs`；`runner.rs` 仅在签名/可见性接线必需时改动
- 上述 crate 的测试
- `docs/runbooks/H06b.md` 的实测结果

禁止：改 V1–V4 迁移、`PROTOCOL.md`、`WHITEBOARD.md`、公共状态枚举；不得把 `lease_node` 重新引入调度器执行路径。

## 交付

1. `NodeExecutor::execute` 接收调度器已领取的 `LeaseGuard`：

```rust
fn execute(
    &mut self,
    node: &PlanNode,
    lease: &LeaseGuard,
    cancel: &CancellationToken,
) -> ExecOutcome;
```

2. `Scheduler::on_started` 返回 guard，或提供等价的 `guard_for(node_id)`；只允许一种获取方式，不能同时维护两套。
3. `ThreadedExecutor` 在 `on_started` 后把 guard clone 传给 worker，worker 不再自行领取。
4. `AgentRunner` 的 `NodeExecutor` 实现直接调用 `run_node_with_lease`；`run_node` 保留为旧调用方包装，但不得被 `ThreadedExecutor` 使用。
5. 测试：
   - 调度器领取的 `lease_token` 与执行器收到的 guard 完全一致；节点记录中只有这一个 token，attempt 只递增一次。
   - 执行器使用错误/过期 guard 时返回 `StaleExecution`，不得产生第二套 `node.started`。
   - 既有 180 passed / 3 ignored 不退化。
6. 更新 `docs/runbooks/H06.md` 的「H06b 待办」：把“把调度器租约真正注入”标为 done，并写实测结果。

测试合计 **187 passed / 3 ignored**（H06 基线 180/3，本轮 +7）：

- `hive-runtime` 23：新增 `on_started_returns_guard_matching_the_claim_without_starting`（调度器 guard 与库内 `lease_token`/`attempt_no` 一致、`ready -> leased` 不产生 `node.started`、跑完后 attempt 仍为 1 且仅一次 `node.started`）、`threaded_passes_scheduler_guard_without_second_lease`（worker 收到的 guard 与调度器已领取租约完全一致、attempt=1、仅一次 `node.started`、无第二个 lease）、`on_finished_propagates_when_executor_settled_the_node`（执行器已把节点结算到终态时调度器只传播 DAG 状态、不重复结算）、`failed_node_retries_without_a_second_node_failed`（执行器已置 `failed` 时 `on_finished(Failed{retryable:true})` 不再 `finish_node`/补发 `node.failed`，按预算进入 `retry_ready/ready`）、`failed_node_finalizes_without_a_second_node_failed`（`retryable:false` 进入 `failed_final`）、`failed_node_with_non_failed_outcome_is_rejected`（`failed` 节点上报非 Failed outcome 返回 `NodeOutcomeMismatch`）；既有 `max_parallel_is_never_exceeded`、`sibling_failure_skips_only_its_downstream`、`reclaim_expired_uses_injected_clock_running_becomes_needs_recovery`、`events_sequence_matches_final_node_states` 按新语义同步断言。
- `hive-agent` 20：新增 `execute_with_stale_guard_returns_failure_without_starting`（错误 guard 返回 `Failed{retryable:false}`、节点保持 `leased`、不产生 `node.started`、租约 token 不变）；既有 `execute_drives_run_node_to_completion` 改为先领取再传 guard 调用 `execute`。

关键行为：

- `Scheduler::on_started` 现在只 `claim_node`（`ready -> leased`），返回 `LeaseGuard`，不再发射 `node.started`；`start_running` 承担 `leased -> running` + `node.started`。
- `ThreadedExecutor` 在 `on_started` 后把 guard 传给 worker；worker 不再自行 `lease_node`。
- `AgentRunner` 的 `NodeExecutor::execute` 直接调用 `run_node_with_lease`，`run_node` 仅作旧调用方包装。
- `on_finished` 在读取 `persisted.state` 后显式处理非终态 `failed`：`failed` + `Failed{retryable}` 直接 `handle_failure`，不再 `finish_node`、不补发第二个 `node.failed`；`failed` + 非 Failed outcome 返回 `RuntimeError::NodeOutcomeMismatch`。
