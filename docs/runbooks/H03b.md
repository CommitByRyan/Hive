# H03b — 真实 Shell 与平台级安全

> 状态：pending；拆成 H03b-1（Shell）与 H03b-2（Win32/网络平台层），可分别验收。
> 输入：`docs/design/H03-tool-security.md`、`docs/runbooks/H03.md`、现有 `hive-policy` / `hive-tools`。

## 目标

把 H03 明确降级的三处能力补到可验证：真实 Shell argv 执行与进程树清理、Windows 句柄级路径遍历、连接级 IP 固定。不能做到的部分必须保持显式降级，不得用应用层检查冒充平台级安全。

## H03b-1：真实 Shell（优先）

允许范围：`crates/hive-tools` 的 `shell.run`、`crates/hive-policy` 的程序/参数策略、对应测试与 runbook。

交付：

1. 默认仍 `shell.enabled=false`；启用后只允许配置中的**规范化绝对程序路径**，默认拒绝 `cmd`、`powershell/pwsh`、`bash/sh` 与解释器。
2. 使用 argv 数组直接 spawn，不经 Shell 解释；`; & $() | >` 等只作为字面参数。
3. 超时、取消、租约失效时终止整个进程树；Windows 用 Job Object（`KILL_ON_JOB_CLOSE`），Unix 用独立进程组。
4. stdout/stderr 有界读取与截断标记；超时返回 `shell.timeout`，清理失败返回 `shell.cleanup_failed`，不能假报成功。
5. 审计仍走 `validate -> policy -> approval -> execute -> audit`，崩溃时保留 started 无 completed，恢复进 `needs_recovery`。

测试：`shell_disabled_and_argv_not_interpreted`、`shell_timeout_kills_descendants_and_truncates`、`shell_program_denied_before_spawn`、`uncertain_shell_completion_requires_recovery`。

依赖：允许 `windows-sys`（仅 `cfg(windows)`，Job Object/Threading 最小 feature）；不引第三方命令解析库。

### 实测结果（H03b-1）

执行命令：

```powershell
$env:HIVE_TOOLCHAIN_ROOT='D:\Downloads\24096\Documents\AAA_codex_code\Hive'
pwsh -NoProfile -File scripts/verify.ps1
```

结果：`fmt`、`clippy --workspace --all-targets -- -D warnings`、`test --workspace` 全部通过（`All checks passed`）。

测试统计：workspace 共 **206 passed / 0 failed / 3 ignored**（基线门槛 187 passed / 3 ignored，无退化）。平台：Windows + GNU 工具链，`windows-sys 0.61`（feature：`Win32_System_JobObjects` / `Win32_System_Threading` / `Win32_Foundation` / `Win32_Security`）。

新增用例：

| 用例 | 结果 |
|---|---|
| `shell_disabled_and_argv_not_interpreted` | 默认 `shell.disabled` 且无 `node.tool_started`；启用后 `;` `$()` `|` `>` 仅作字面 argv，无第二进程副作用 |
| `shell_timeout_kills_descendants_and_truncates` | stdout 截断到 `max_output=512` 且 `truncated=true`；2s 超时返回 `shell.timeout`，Job Object 关闭后后代未写 `finished.txt`（未存活） |
| `shell_program_denied_before_spawn` | 绝对 `cmd.exe` 与相对程序均在 spawn 前返回 `shell.program_denied`，无 `node.tool_started` |
| `uncertain_shell_completion_requires_recovery` | `[intent, started]` 无 completed → `NeedsRecovery`；Store 租约过期后 `running -> needs_recovery` |

降级声明：`CreateJobObjectW` 需要 `Win32_Security`（`SECURITY_ATTRIBUTES`），已并入 feature；Job Object 在 `spawn` 后立即分配，理论上存在极小「父进程抢先 spawn 孙进程」竞态窗口（测试 helper 延迟 200ms 规避）。Unix 独立进程组 + `kill` 杀组路径本机未实机验证。

## H03b-2：Win32 句柄与连接级 IP

允许范围：新建 `crates/hive-platform`（平台 trait 与 Windows 实现）、`hive-policy` 的路径/网络策略接线、测试与 runbook。`hive-workspace` 名字已被 H06 的 git worktree 占用，禁止复用。

交付：

1. 根目录句柄 + 逐段 `FILE_FLAG_OPEN_REPARSE_POINT` 打开；最终路径用 `GetFinalPathNameByHandleW` 与根句柄比较；拒绝 reparse 逃逸、跨卷、ADS、UNC、8.3 短名歧义。
2. 写入不存在叶文件时，从最长已存在祖先逐段创建并复核；叶文件以不可跟随链接方式创建。
3. 网络请求一次解析、校验全部 A/AAAA，仅连接已验证 IP，TLS SNI/Host 保持域名；连接后复核 peer IP；默认不重定向。
4. 非 Windows 构建明确能力等级，不伪装同等保证。

测试：`open_handle_detects_toctou_swap`（从 ignored 转真跑或明确平台跳过）、`policy_rejects_symlink_escape`、`network_blocks_private_metadata_and_bad_ports`、`network_pins_validated_ip`。

若底层客户端无法固定 peer IP，则只交付策略层并明确声明“应用层 SSRF 限制，未防 DNS rebinding”，不得声称完成。

### 实测结果（H03b-2）

执行命令：

```powershell
$env:HIVE_TOOLCHAIN_ROOT='D:\Downloads\24096\Documents\AAA_codex_code\Hive'
pwsh -NoProfile -File scripts/verify.ps1
```

结果：`fmt`、`clippy --workspace --all-targets -- -D warnings`、`test --workspace` 全部通过（`All checks passed`）。

测试统计：workspace 共 **236 passed / 0 failed / 1 ignored**。基线为 rebase 后 main `97cefa7`（含 H03b-1 与 H10）的 **227 passed / 3 ignored**，无退化；2 个原 `#[ignore]` 的 hive-policy 用例转真跑，ignored 降至 1（仅剩 hive-llm 的 Magpie 冒烟）。

平台：Windows + GNU 工具链，`windows-sys 0.59`（feature：`Win32_Foundation` / `Win32_Security` / `Win32_Storage_FileSystem`）。新增依赖仅此一个，且 `cfg(windows)` 限定；`hive-policy` 新增 `hive-platform` 路径依赖。

新增/转真用例：

| 用例 | 结果 |
|---|---|
| `open_handle_detects_toctou_swap`（原 ignore，现真跑） | `mklink /J` 建 junction 替换目录后，`authorize_handle` 返回 `path.reparse_escape`，不再用原路径继续 |
| `policy_rejects_symlink_escape`（原 ignore，现真跑） | 根内 junction 指向外部时，句柄级遍历在 `link` 段检测 reparse 并拒绝 `path.reparse_escape` |
| `network_blocks_private_metadata_and_bad_ports` | `169.254.169.254`、loopback、私网、link-local、`::ffff:127.0.0.1` 映射与未放行端口均在 connect 前拒绝 |
| `network_pins_validated_ip` | IP 字面量一次解析并固定；`connect_pinned` 直连已验证 IP 且 `peer == 目标地址`；`connection_pinning=true` 而 `dns_rebinding_resistant=false` |
| `hive-platform` 5 个测试 | 句柄读文件 final_path 在根内、缺失父目录/叶文件逐段创建、IP 字面量解析、pin 连接 peer 校验、peer 不匹配拒绝 |

平台能力矩阵：

| 能力 | Windows | 非 Windows |
|---|---|---|
| 句柄级路径（`FILE_FLAG_OPEN_REPARSE_POINT` 逐段 + `GetFinalPathNameByHandleW`） | `true` | `false`（canonicalize 回退，显式降级） |
| reparse 检测 / 最终路径复核 / 跨卷拒绝 | `true` | `false` |
| 连接级 IP 固定原语（一次解析、固定 IP、peer 复核） | `true` | `true`（std TCP） |
| 端到端 DNS-rebinding 抗性 | `false` | `false` |

降级声明：

1. **网络端到端仍是应用层限制。** `hive-platform` 提供 `resolve_all` / `connect_pinned`（一次解析 + 固定已验证 IP + 连接后复核 peer IP）与 `hive-policy::NetworkPolicy::resolve_and_validate` / `connect_validated`，但 `hive-llm` 的 `ureq` transport 未改接该原语，仍由客户端自行 DNS。因此端到端声明为“**应用层 SSRF 限制，未防 DNS rebinding**”（`NetCapabilities::dns_rebinding_resistant=false`），不声称完成连接级固定。
2. **非 Windows 路径未实现句柄级。** `FallbackPathPlatform` 走 `canonicalize + 前缀复核`，`PathCapabilities` 三项均为 `false`，TOCTOU 窗口仍存在；不据此宣称跨平台句柄级隔离。
3. **8.3 短名/别名**通过最终路径末段与请求段大小写不敏感比对拒绝（返回 `path.unsupported_form`），无独立专测；ADS/UNC/设备路径仍由 `hive-policy` 词法层拒绝（既有测试覆盖）。
4. **junction 用例依赖 NTFS。** 两个 Windows 用例用 `cmd /c mklink /J` 建目录 junction（非管理员可建）；若环境不可建则打印 SKIP 并直接通过，不据此声称已在无 NTFS 环境验证。
