# H09c — 可观测性与数据保留

> 状态：ready after H09b merge；基线以合并后 main 为准
> 依据：`docs/design/H09-recovery-observability.md` §5、`docs/ADR/0005-budget-routine-recovery.md` D5/D7/D9

## 目标

在不引入新观测依赖的前提下，提供结构化日志、共享 trace、指标注册表、分级健康检查和可测试的数据保留/归档；清理不得重写 `seq`、不得部分删除活跃 Mission。

## 允许范围

- `crates/hive-store`：保留/归档查询与清理、`retained_since_seq`、Mission 段审计校验；只追加方法，不改 V1–V6 schema。
- `crates/hive-runtime`：trace 注入、恢复/调度指标埋点。
- `crates/hive-server`：`/api/health` 追加字段、`/api/health/live`、`/api/health/ready`、指标只读暴露。
- `crates/hive-agent`：Turn/工具 span 与日志字段。
- 对应测试与 `docs/runbooks/H09c.md` 实测结果。

禁止：引入 `tracing`/`metrics`/`tower-http`；改 H08 已冻结字段；删除活跃 Mission 事件；改 PROTOCOL/WHITEBOARD/ADR。

## 交付

1. **结构化日志**：JSON Lines 到 stderr；固定字段 `ts/level/trace_id/span_id/mission_id/run_id/node_id/attempt_no/session_id/tool/model/msg/target`；不输出密钥/完整请求头。
2. **trace 共享**：Node 领取生成 `tr_` trace；Turn/工具子 span；事件 `trace_id` 与日志同源；至少一个测试断言同节点日志与 `node.started` 的 trace 一致。
3. **指标注册表**：按设计 §5.3 的清单，`AtomicU64` counter/gauge + 固定桶直方图；标签只取有界枚举，超限归 `other`，不暴露具体值。
4. **健康分级**：保留 H08 `/api/health` 字段，追加 `status/checks/budget`；新增 `/api/health/live`、`/api/health/ready`；`degraded` 返回 200。
5. **保留/归档**：终态 Mission 超过阈值整段归档到 `data/archive/<mission_id>/events.jsonl`，再删行；活跃 Mission 一条不少；`latest_seq` 不变；发布 `retained_since_seq`。
6. **审计链**：活跃期保持全局 `tool_audit` 链；归档段写 `segment_genesis_hash`，按 Mission 段校验；不重写 `seq`。
7. 测试覆盖设计 §5.6 的 7 条 + 归档后段内审计校验 + `after_seq < retained_since_seq` 强制快照提示。

### 结构化日志与 trace

- `hive-runtime::logging` 输出 JSON Lines 到 stderr，固定字段顺序为 `ts/level/trace_id/span_id/mission_id/run_id/node_id/attempt_no/session_id/tool/model/msg/target`；不记录 prompt、请求头或密钥。
- `start_capture()` / `LogCapture::records()` 是默认关闭的测试钩子；开启时把同一行 JSON 写入内存缓冲，关闭时只做一次原子判断，不改变生产 stderr 路径。
- Node 领取时生成 `TraceId`，`node.started/node.turn/node.succeeded`、工具事件与 `node execution started` 日志共享同一 `trace_id`；缺失 trace 的失败/取消/拒绝路径已补齐 `Some(scope.trace_id)`。

### 指标注册表

- `hive-runtime::metrics` 使用 `AtomicU64` counter/gauge 与固定桶直方图 `[1,2,5,10,20,50,100,250,500,1000]`（毫秒）。
- 标签按指标维护已见集合，超过基数上限后折叠为 `other`，原始标签值不会出现在 `snapshot()` 输出中。
- `/api/health` 的 `budget.exceeded_total` 从 `hive_budget_exceeded_total` 快照按 dimension 汇总；出现预算超限时 `status` 为 `degraded`。

### 健康分级

- `/api/health`：保留 H08 字段，追加 `status`、`checks`（database/model_catalog/approvals/budget）、`budget`、`metrics`、`retained_since_seq`；审批积压或预算超限返回 200 + `status:"degraded"`。
- `/api/health/live`：SQLite `PRAGMA` 可读即 200，否则 503。
- `/api/health/ready`：`SCHEMA_VERSION` 不匹配或模型目录为空返回 503，否则 200。

### 归档形状与游标

归档目录为 `data/archive/<mission_id>/events.jsonl`，写入完成后 `flush + sync_all`，随后在同一事务删除 `events`、`tool_audit` 与该 Mission 的 `snapshots`。文件内容：

```text
第 1 行  {"mission_id","archived_at_ms","event_count","audit_count","segment_genesis_hash"}
随后 N 行 原始 EventEnvelope JSON（保持入库字节与 seq）
随后 M 行 {"record_json","prev_hash","entry_hash"}
```

- `segment_genesis_hash` 取该 Mission 首条审计的 `prev_hash`，空集合为 `"GENESIS"`；段内校验逐条检查 `prev_hash` 与 `audit_entry_hash(prev_hash, record_json)`，不重写 `seq`。
- 保留阈值使用严格 `<`：`updated_at_ms == now_ms - 30d` 不归档。
- `latest_seq()` / `latest_seq_on()` 取 `MAX(events.seq)` 与 `sqlite_sequence` 高水位的大者，归档后不下降。
- `retained_since_seq` 为已归档段最大 `seq + 1`，归档前为 0；`/api/events` 先读该值再查 backlog，`after_seq < retained_since_seq` 返回 `409 {"snapshot_required":true,...}`，`after_seq == retained_since_seq` 返回正常 SSE。

### 已知残余风险

- `retained_floor` 只保存在 Store 进程内，重启后回到 0；跨重启的归档游标需要 V7 元数据表，当前未引入。
- 归档尚未接入生命周期 tick 自动调度，目前由调用方显式执行 `archive_mission` / `archive_expired_missions`。
- 归档失败（创建目录、写入、`sync_all` 或事务）保持 fail-closed：不删除任何行并返回 `StoreError::Archive`；未在非 Windows 文件系统上做 `sync_all` 语义实测。
