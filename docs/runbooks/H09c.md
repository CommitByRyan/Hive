# H09c — 可观测性与数据保留

> 状态：ready after H09b merge；基线以合并后 main 为准
> 依据：`docs/design/H09-recovery-observability.md` §5、`docs/ADR/0005-budget-routine-recovery.md` D5/D7/D9

## 目标

在不引入新观测依赖的前提下，提供结构化日志、共享 trace、指标注册表、分级健康检查和可测试的数据保留/归档；清理不得重写 `seq`、不得部分删除活跃 Mission。

## 允许范围

- `crates/hive-store`：保留/归档查询与清理、`retained_since_seq`、Mission 段审计校验；只追加方法，不改 V1–V6 schema。
- `crates/hive-runtime`：trace 注入、恢复/调度指标埋点。
- `crates/hive-server`：`/api/health` 追加字段、`/api/health/live`、`/api/health/ready`、指标只读暴露。
- `crates/hive-agent`：Turn/工具 span 与日志字段。
- 对应测试与 `docs/runbooks/H09c.md` 实测结果。

禁止：引入 `tracing`/`metrics`/`tower-http`；改 H08 已冻结字段；删除活跃 Mission 事件；改 PROTOCOL/WHITEBOARD/ADR。

## 交付

1. **结构化日志**：JSON Lines 到 stderr；固定字段 `ts/level/trace_id/span_id/mission_id/run_id/node_id/attempt_no/session_id/tool/model/msg/target`；不输出密钥/完整请求头。
2. **trace 共享**：Node 领取生成 `tr_` trace；Turn/工具子 span；事件 `trace_id` 与日志同源；至少一个测试断言同节点日志与 `node.started` 的 trace 一致。
3. **指标注册表**：按设计 §5.3 的清单，`AtomicU64` counter/gauge + 固定桶直方图；标签只取有界枚举，超限归 `other`，不暴露具体值。
4. **健康分级**：保留 H08 `/api/health` 字段，追加 `status/checks/budget`；新增 `/api/health/live`、`/api/health/ready`；`degraded` 返回 200。
5. **保留/归档**：终态 Mission 超过阈值整段归档到 `data/archive/<mission_id>/events.jsonl`，再删行；活跃 Mission 一条不少；`latest_seq` 不变；发布 `retained_since_seq`。
6. **审计链**：活跃期保持全局 `tool_audit` 链；归档段写 `segment_genesis_hash`，按 Mission 段校验；不重写 `seq`。
7. 测试覆盖设计 §5.6 的 7 条 + 归档后段内审计校验 + `after_seq < retained_since_seq` 强制快照提示。

## 完成标准

- `pwsh -NoProfile -File scripts/verify.ps1` 全绿，H08/H09a/H09b 既有测试不退化。
- 真实命令与测试数字写入 runbook；日志/指标输出不含密钥。
- handoff 五段：状态 / 改动文件 / 验证证据 / 遗留风险 / 建议下一步。
- 模型：`auto/glm-5.3` 主写日志/健康/前端可见字段；清理与审计段用 `auto/deepseek-v4-pro` high 复核。
