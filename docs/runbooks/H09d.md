# H09d — 恢复入口、租约事件与生命周期 tick

> 状态：ready after H09b merge；基线以合并后 main 为准
> 依据：R08 P1-1/P1-2、ADR 0005 D2/D3/D4、H09b 的 Routine tick 交付

## 目标

把已经实现但未接生产入口的启动恢复、预算重建、租约回收和 Routine tick 接入统一生命周期；租约回收的状态转移必须在同一事务写事件。只改接线与事件，不重写恢复算法。

## 允许范围

- `crates/hive-store`：`reclaim_expired_leases` 事务化事件；对应测试。
- `crates/hive-runtime`：启动/周期 tick 的编排 helper；测试。
- `crates/hive-server`：main/AppState 的启动顺序与后台 tick 生命周期；测试。
- `docs/runbooks/H09d.md` 实测结果。

禁止：改 V1–V6 schema、PROTOCOL/ADR/白板、Routine 表达式语义、恢复五步顺序；不引入新依赖、不引入 tracing/metrics。

## 交付

1. **租约回收事件**：`reclaim_expired_leases` 对每个实际转移在同一 `IMMEDIATE` 事务内写事件：
   - `leased -> ready`：`node.ready`；
   - `running -> needs_recovery`：`node.needs_recovery`（reason=lease_expired）；
   - CAS 失败/已回收的行不重复发事件；返回的节点与事件一致。
2. **启动入口**：提供可测试的 startup helper，顺序固定为 `run_startup_recovery` → `rebuild_budget_counters`；`hive-server::main` 在绑定端口/接受请求前调用，失败即拒绝启动。
3. **周期生命周期**：server 启动一个可停止的后台 tick，周期调用 `tick_routines` 与 `reclaim_expired_leases`；单次错误计入结果但不杀死循环。周期值可配置或有安全默认，测试用注入时钟/短周期。
4. **可停止/可恢复**：退出时停止 tick，不遗留阻塞线程；重复启动恢复幂等，不重复副作用。
5. **测试**：
   - `lease_reclaim_writes_ready_event_in_same_transaction`；
   - `lease_reclaim_writes_needs_recovery_event`；
   - `startup_helper_runs_recovery_then_rebuilds_budget`；
   - `server_startup_rejects_work_before_recovery`（至少验证 helper 顺序/失败关闭）；
   - `tick_loop_fires_due_routine_and_reclaims_expired_lease`；
   - 既有恢复/H09b Routine 测试不退化。
