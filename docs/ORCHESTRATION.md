# Hive Rust 重构 — 对话编排手册

> 回答三个问题：拆成几个板块、分几个对话、每个对话用什么模型。
> 本文件由 H00 维护；所有实施对话开工前必须先读 `WHITEBOARD.md` 与本文件对应小节。

## 1. 为什么必须拆对话

| 原因 | 具体表现 | 后果 |
|---|---|---|
| 上下文是稀缺资源 | 一个对话同时容纳 schema、工具沙箱、DAG 调度、HTTP、前端 | 到中段开始丢早期约束，产出前后矛盾 |
| 写冲突 | 两个对话同时改 `hive-types` 或同一迁移目录 | 合并不如重写，返工成本高 |
| 可审计 | 一个对话既是实现者又是验收者 | 自己给自己打分，缺陷被掩盖 |
| 模型差异 | 契约推理、工具密集实现、长文整合对模型要求不同 | 用错模型会反复工具调用失败或推理变浅 |

结论：**按可独立验收的垂直切片拆对话**，不是按文件拆，也不是按“前端/后端”拆。

## 2. 板块划分

产品重点是高性能多 Agent 协作，因此板块顺序是“状态与恢复 → 安全边界 → 单 Agent 闭环 → 并行 DAG → 多 Agent 协作 → 服务面 → 质量与发布”。

| 板块 | 覆盖阶段 | 一句话职责 | 不可让步的点 |
|---|---|---|---|
| A 契约与骨架 | H00、H01 | 定义 ID、状态机、事件、协议、工程结构 | 契约先冻结，代码后跟进 |
| B 持久化与恢复 | H02 | SQLite、事务事件、seq 游标、快照 | 状态与事件同事务，重启可续 |
| C 工具与安全 | H03 | 工具注册、审批、路径/网络/Shell 边界 | 默认拒绝，审批可超时 |
| D 执行内核 | H04、H05 | 单 Agent 闭环、并行 DAG、租约、取消、预算 | 可取消、可恢复、不重复副作用 |
| E 多 Agent 协作 | H06 | 结构化 handoff、worktree、集成者 | 不倾倒完整对话历史 |
| F 网关与服务面 | H07、H08 | 模型网关、HTTP/SSE、Web 控制台 | 单一状态所有者，客户端只读事件 |
| G 质量与发布 | H09、H10、H11 | 定时、可观测、评估、故障注入、发布 | 每条验收有真实命令证据 |

## 3. 对话清单

每个对话是一张卡。卡外的内容一律不做。

### H00 总控

- 输入：用户目标、各对话 handoff。
- 输出：白板、契约文档、ADR、集成与最终验证。
- 禁止：替实施对话写业务代码；一次接两个实现任务。
- 验收：workspace 全绿 + 白板与实现一致。
- 模型：`workbuddy/deepseek-v4-pro`。

### H01 契约与骨架（已完成）

- 输入：H00 冻结契约。
- 输出：`hive-types`、`hive-config`、`hive-cli doctor`。
- 验收：fmt、clippy、test、build、doctor 全通过。

### H02 持久化与事件

- 输入：`docs/PROTOCOL.md`、`docs/ADR/0002-execution-recovery.md`、H01 代码。
- 输出：`hive-store`、`hive-events`、迁移 V1、AttemptNo/LeaseToken。
- 禁止：Tokio、HTTP、调度逻辑、工具执行。
- 验收：空库迁移、重复事件幂等、慢订阅者不阻塞、强杀恢复不重跑已确认副作用。
- 模型：首轮 `deepseek-v4-pro` 定 schema，主体实现 `deepseek-v4.1-flash`，收尾复审回 pro。

### H03 工具、审批与安全

- 输入：`docs/ADR/0004-security-boundaries.md`、H01 代码。
- 输出：工具注册表、参数校验、路径策略、网络策略、Shell 策略、审批状态机与超时、审计记录。
- 禁止：真实调用模型、调度、持久化 schema 改动。
- 验收：越界路径被拒、审批超时转 expired、单节点审批不阻塞其他分支、Windows 路径规范化用例。
- 模型：`deepseek-v4-pro` 主写，`mimo-v2.6-pro` 只做平台细节审查。

### H04 单 Agent 垂直闭环

- 输入：H02 存储、H03 工具、H07 网关（可先用 stub）。
- 输出：一次 prompt → 模型 → 工具 → 结果 → 事件落库的完整闭环。
- 验收：一次成功运行的全链事件可回放；工具失败可重试；取消能中断。
- 模型：`deepseek-v4-pro`。

### H05 并行 DAG 调度

- 输入：H04 闭环。
- 输出：依赖解析、就绪队列、租约续期、并发上限、预算、取消传播、重试退避。
- 验收：菱形 DAG 并行正确、单节点卡住不影响兄弟节点、取消在 2s 内传播、租约过期可被回收。
- 模型：`deepseek-v4-pro`。

### H06 多 Agent 协作

- 输入：H05 调度。
- 输出：结构化 handoff、Agent 角色、worktree 生命周期、集成者合并策略。
- 验收：两个 Agent 并行改不同 worktree 不互相污染；handoff 丢失时可从事件重建。
- 模型：`deepseek-v4-pro`，文档段落可切 `deepseek-v4.1-flash`。

### H07 模型网关

- 输入：Magpie `http://127.0.0.1:3425/v1`、H01 配置。
- 输出：OpenAI 兼容客户端、流式解析、超时/重试/退避、模型别名与能力表、token 计量。
- 禁止：调度、工具执行、UI。
- 验收：流式增量正确拼接、429/5xx 重试有上限、取消能断开连接、未知模型报错清晰。
- 模型：`deepseek-v4.1-flash` 主写，流式与重试语义段落切 `deepseek-v4-pro`。

### H08 服务协议与 Web 控制台

- 输入：H05、H07。
- 输出：HTTP API、SSE 事件流、JSON-RPC、最小控制台。
- 验收：断线重连用 `seq` 补齐、两个客户端状态一致、控制台可暂停/取消/审批。
- 模型：`glm-5.3` 主写，SSE 并发段落切 `deepseek-v4-pro`。

### H09 定时、恢复与可观测

- 输入：H02、H08。
- 输出：cron/定时任务、崩溃恢复扫描、指标、结构化日志、数据保留策略。
- 验收：重启后 `needs_recovery` 节点按策略处置；指标可区分排队/执行/等待审批。
- 模型：`deepseek-v4.1-flash`。

### H10 评估、故障注入与性能

- 输入：H06。
- 输出：基准场景、故障注入器、并发/吞吐/恢复时间报告、安全回归用例。
- 验收：报告可复现，数字有采集脚本，不以单次运行为结论。
- 模型：`deepseek-v4.1-flash`，故障注入设计切 `deepseek-v4-pro`。

### H11 发布与迁移

- 输入：H10 报告。
- 输出：安装包、版本与迁移策略、回滚手册、发布说明。
- 验收：干净机器可安装；旧数据迁移有 dry-run；回滚步骤演练过。
- 模型：`deepseek-v4-pro` + 独立审计对话。

## 4. 模型选择依据

| 模型 | 强项 | 适合 | 不适合 |
|---|---|---|---|
| `workbuddy/deepseek-v4-pro` | 长链推理、状态机、并发语义 | 契约、schema、调度、恢复、复审 | 大量机械样板 |
| `workbuddy/deepseek-v4.1-flash` | 工具调用稳、改动快 | 实现主体、测试补齐、脚手架 | 复杂并发证明 |
| `workbuddy/kimi-k3.1-pro` | 长上下文、独立判断 | 只读审计、契约复核 | 长跑实现 |
| `workbuddy/glm-5.3` | 长文组织、协议与 UI | Web 控制台、文档整合 | 深水区并发 |
| `workbuddy/mimo-v2.6-pro` | 平台细节、安全视角 | Windows/进程/权限审查 | 大批量打补丁 |
| `workbuddy/minimax-m3.1-flash` | 快速草稿 | 文档初稿、样例数据 | 关键路径 |

切换规则：

1. 一个对话内只在**阶段边界**换模型，不在同一轮实现中途换。
2. 工具调用连续失败两次 → 换模型重试一次；仍失败 → H00 接管并拆小任务。
3. 审计对话与被审对话不能是同一模型实例。

## 5. 白板协议

- 唯一白板：`WHITEBOARD.md`，只有 H00 写。其他对话通过最终回复 handoff。
- 每个对话开工第一件事：读 `WHITEBOARD.md` → 读自己的 `docs/runbooks/Hxx.md` → 读 `AGENTS.md`。
- 每个对话开工第一件事之后：先给 3–5 步计划，再写代码。
- handoff 固定五段：状态 / 改动文件 / 验证证据 / 遗留风险 / 建议下一步。
- 白板冲突时以白板为准；文档与白板不一致，先报 H00。

## 6. 每轮标准动作

1. 读白板与 runbook，确认自己没有被冻结。
2. 输出 3–5 步计划，每步可验证。
3. 小步实现，先跑最接近的检查。
4. 交付前跑该阶段规定的完整命令，保存输出摘要。
5. 写 runbook 的「实测结果」，按五段格式 handoff。

## 7. 并行与冲突

- 并行前提：有稳定基线 commit + 每个实现对话独立 worktree。
- 同时最多两个实现对话；第三个只能是只读审计或独立测试脚手架。
- 两个实现对话不得改同一 crate、同一迁移目录、同一协议文件。
- 集成由 H00 做：按白板顺序合并，合并后重跑全量检查。
- 无基线时只允许单写者，宁慢不乱。

## 8. 失败模式与处置

| 失败模式 | 识别信号 | 处置 |
|---|---|---|
| 上下文漂移 | 改动开始违背冻结契约 | 立即停，回读 PROTOCOL，必要时重开对话 |
| 工具调用格式错误 | 连续两次调用被解析失败 | 换模型；仍失败则拆成更小任务 |
| 越界改动 | diff 出现范围外文件 | 回滚该对话产物，H00 重派 |
| 只写不验 | 声称完成但无命令输出 | 不接受，退回补验证 |
| 并行写冲突 | 同一文件两边都改 | 停止并行，改单写者 |
